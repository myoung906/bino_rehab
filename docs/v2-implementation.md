## 기준 사진과 보정

개인 기준 사진은 iPhone 12 mini 전면카메라, 4032×3024 원본, 렌즈–각막 40cm이다.
판독한 두 중심 간격 약 502.2px와 사용자가 제공한 원거리 IPD 65.5mm를 이용해
`65.5 / 502.2 ≈ 0.1304mm/px`로 역산했다. 이 값은 개인 보정 표본이며 독립적으로 검증된 공통 카메라 상수가 아니다.
원본 사진 자체는 리포에 복사하지 않았다.

사진 방식은 같은 사용자·렌즈·촬영 범위·잘림을 확인하고 종횡비가 일치할 때
`영상 mm/px = 사진 mm/px × 사진 폭 / 실제 영상 폭`으로 환산한다.
확인이 어려울 때는 원거리 주시 5초 동안 실제 IPD를 기준으로 현재 영상의 mm/px를 구하는 별도 방식을 제공한다.
이 경우 결과는 `known-ipd-calibrated`로 표시하여 입력한 IPD를 재확인한 독립 측정으로 취급하지 않는다.
기기 ID, 실제 영상 폭·높이, 카메라 방향, 지원되는 경우 줌 설정을 보정 범위에 포함한다.

시선각도와 화면 물리 크기는 길이 보정과 독립적이다. 시선각도 계수가 없는 차폐 관측은
이동을 기록하지만 Δ 또는 AC/A를 생성하지 않는다. 사용자를 바꿀 때에는 새 사용자 설정으로 개인 보정을 초기화한다.

## 검사 순서

1. 처음 설정: 길이 보정 방식, 실제 먼 표적 거리, 굴절교정 상태를 기록한다.
2. 원거리 IPD: 카메라는 40cm, 눈은 먼 표적을 5초간 주시한다. 유효 중심·머리 안정 구간의 중앙값을 사용한다.
3. 원거리 차폐: 오른눈·왼눈 단순 차폐를 먼저 관찰한 후, 번갈아 각 눈 5회씩 차폐→해제→재주시를 관찰한다.
4. 근거리 IPD: 렌즈를 40cm에서 5초간 주시하며 근거리 기준을 별도로 기록한다.
5. 근거리 차폐: 같은 사건 관측 방식으로 근거리 이동을 수집한다.
6. NPC: 렌즈를 주시하며 접근한다. 접근이 이어지는 동안 한 눈이 멈추거나 밖으로 이동하는 후보를 관찰한다.
7. 오른눈 단안 조절력: 40cm로 돌아와 잠깐 먼 곳을 주시하고 왼눈을 가린다. 40cm에서 시표가 읽히는 것을 확인하고 접근한다.
8. 왼눈 단안 조절력: 반대쪽 눈을 가리고 동일하게 시행한다.
9. 결과: 유효값과 미측정·무효·시간 내 종료점 미관측 상태, 계산 방법과 거리 기준을 표시하고 JSON으로 저장할 수 있다.

시작·완료·다음 차폐·2초 차폐 후 해제에 짧은 삐 소리를 사용한다.
차폐 횟수는 소리 횟수가 아니라 손 겹침, 해제 후 실제 유효 관측으로 센다.
얼굴 또는 동공 추적 손실, 양안 동시 차폐, 큰 머리 움직임, 촬영 범위 변경은 계산에 포함하지 않는다.

## 영상 관측

- MediaPipe Face Landmarker의 본인 기준 오른눈 468..472, 왼눈 473..477을 사용한다. 표시만 미러링한다.
- 홍채 위치를 ROI 초기값으로 사용하여 밝은 반사를 제외한 어두운 연결 영역을 탐색한다.
  면적·중심 이탈·형태·경계 대비 조건을 만족한 영역만 동공 후보로 채택한다.
  후보를 찾지 못하면 홍채 중심으로 동공을 대체하지 않는다.
- 눈꼬리 축에서 위치를 눈 폭으로 정규화하여 평면 머리 이동·회전과 거리 배율의 영향을 줄인다.
- Hand Landmarker의 손 랜드마크 볼록 껍질과 눈 위치의 겹침을 차폐 후보로 사용한다.
  이 조건만으로 빛이 완전히 차단되었다고 보장하지 않으므로 사용자가 눈 전체를 가리는 안내를 지켜야 한다.
- 카메라 프레임은 중복 디코딩 시간을 제외하고 처리하며, RAF·스트림·모델을 종료할 때 정리한다.
- 앱이 백그라운드로 가거나 영상이 정지하면 검사 단계를 중단한다.

이 동공·차폐 판독은 초기 알고리즘이다. 어두운 홍채, 안경 반사, 근접 촬영에서의 가림과 초점 변화에 대한 성능은 실기기에서 확인해야 한다.

## 시선각도 보정과 사위

검사자 설정에서 실제 각도를 아는 중앙·좌·우·상·하 표적을 사용한다.
각 눈의 실제 표적각도를 별도로 입력하고, 안정 관측 위치와 각도의 관계를 눈별·축별 선형 회귀한다.
미러링 전 영상 기준 오른쪽·아래쪽 방향을 +로 입력한다. 양방향 표적, 충분한 위치 변화,
회귀 잔차 조건을 만족할 때에만 계수를 저장하며, 같은 촬영 범위에서 사용한다.
보정계수를 정하려면 표적 위치·안구회전점·거리의 기하학적 배치를 별도로 측정해야 한다.
한 장의 IPD 사진은 이 과정을 대체하지 않는다.

사위 관측은 해제 직후 유효 위치에서 안정된 재주시 위치까지의 이동을 사용한다.
수평은 내사위 + / 외사위 −, 수직은 오른눈 상대 상사위 + / 하사위 −로 눈별 부호를 맞춘다.
`Δ = 100 × tan(보정된 각도)`를 적용하고 각 눈 5회 이상 유효 관측을 요구한다.
처음 단순 차폐에서 반대 눈의 움직임이 관찰되면 사위량 해석을 보류한다. 이 관찰 자체를 사시 진단으로 표시하지 않는다.

구형 `atan(동공 이동 mm / 413mm)`를 보정 없이 임상 사위량으로 사용하지 않는다.
동공 이동량과 표적 평면의 이동량은 다른 관측이다.

## 거리와 종료점

40cm 근거리 기준 홍채 크기와 현재 크기의 비율로 접근 거리를 추정한다.
기본적으로 홍채 관측 평면과 각막을 같은 평면으로 근사하고, 필요 시 mm 오프셋을 설정한다.
오프셋을 설정한 경우 기준과 현재 거리 모두에 반영하여 40cm 기준이 유지되도록 한다.

IPD 기반 거리도 별도 비교 기록으로 남긴다. 폭주 자체가 투영 동공 간격을 바꾸므로
홍채 거리와 무조건 평균하지 않는다. 단안검사에서는 열린 눈의 홍채 방식만 사용한다.
따라서 두 방법의 절대 정확도를 비교·선택하려면 실제 거리 참조와 함께 동영상을 수집해야 한다.

NPC 후보는 유효 양안 추적, 머리 방향 안정, 지속 접근 조건에서 눈별 안쪽 움직임 속도를 비교해 찾는다.
지속 확인 후에도 첫 후보의 시간·거리를 기록한다. 표시값은 각막 기준 추정 거리에 회전점 오프셋 13mm를 더한 값이다.
정지·밖으로 이동 판정의 임계값은 프로토타입 설정이며 외안근의 기계적 한계를 직접 측정했다고 해석하지 않는다.
얼굴·눈 추적 손실을 NPC break로 대체하지 않는다.

조절력은 각 눈 단독으로 검사한다. 란돌트 C는 40cm에서 소수시력 0.66에 해당하는
외경 약 0.88mm, 틈 약 0.18mm 크기로 화면 물리 크기를 보정한 뒤 고정한다.
접근에 따라 크기를 다시 계산하지 않는다. 방향은 간헐적으로 바꿔 기억에 의한 판독을 줄인다.
40cm에서 판독하지 못하면 미측정으로 남긴다. 읽을 수 없어진 시점에 휴대폰을 멈추고 탭하며,
최근 열린 눈 관측과 정지 구간에서 거리 중앙값을 구한다.
`D = 100 / 각막–시표 거리(cm)`를 계산하고 렌즈→화면의 거리 보정을 적용한다.
이 결과는 사용자가 선택한 고정 시표 판독불가 방식의 근점 버전스이며, 표준 첫 지속 흐림 검사나 객관 조절력과 동등함이 검증된 값은 아니다.
굴절교정 상태를 함께 기록한다.

## AC/A와 제거한 추정

`AC/A = IPD(cm) + (근거리 수평사위 − 원거리 수평사위) / 2.5`를 사용한다.
유효한 수평사위와 원거리 IPD, 원거리 표적 6m 이상, 원거리 굴절교정 기록이 있어야 출력한다.
수직사위는 계산에 사용하지 않는다.

자유 녹화로 생성하던 근거리 사위 1.5배, PRC/NRC 배수, 홍채 면적 기반 PRA/NRA,
IPD/프리즘 기반 NPC, 나이에 의한 최대조절력 대체값은 결과에서 제거했다.
렌즈·프리즘 없이 측정하지 않은 항목에 숫자를 생성하지 않는다.

## 구현 상태

계산 함수, 보정 데이터, 검사 단계, 동공·손 관측, 안내 화면과 결과 저장을 작성했다.
사용자가 빌드·테스트·테스트용 실행을 승인했다. v1 추정 공식을 기대하던 계산 테스트를
v2 검증 사례로 교체하고, 사진·영상 보정, 단안 거리, 시선각도 회귀의 테스트를 추가했다.
2026-10-06 사용자가 Node.js 22.23.3 및 npm 12.2.0, 의존성 설치를 마쳤다.
`tsc --noEmit` 통과, `npm run lint` 경고·오류 없이 통과,
`npm test`는 2개 파일의 29개 테스트 전부 통과했다.
Google Fonts 다운로드 실패를 해결하기 위해 시스템 글꼴을 사용하도록 수정했다.
기본 Turbopack은 내부 포트 바인딩이 실행 환경 정책에 막혀 실패했지만,
`npm run build:standalone -- --webpack`은 정상 완료했고 정적 출력 `web/out`을 생성했다.
`npm run dev -- --hostname 127.0.0.1 --port 3000` 서버 시작은
`listen EPERM`으로 거절됐다. 서버가 실행되었다거나 브라우저에서 확인했다고 보고하지 않는다.
사용자의 일반 터미널에서 다음 명령으로 테스트 서버를 실행할 수 있다.

```bash
source ~/.nvm/nvm.sh
cd /home/optinex/Documents/workspace/bino_rehab/v2/web
npm run dev -- --webpack --hostname 127.0.0.1 --port 3000
```

같은 컴퓨터의 브라우저에서 `http://localhost:3000`에 접속한다.
휴대폰 원격 카메라 테스트에는 별도의 신뢰할 수 있는 HTTPS 연결이 필요하다.
추가 패키지 없이 Node.js의 TypeScript 타입 제거와 `node:assert/strict`를 사용하여
실제 보정·계산·각도 회귀 함수를 불러온 직접 검증 13개는 통과했다.
검증 대상은 사진 보정 적용 조건, 종횡비 거부, IPD 환산, 잘못된 IPD 입력,
각도→프리즘 변환, AC/A 공식과 NaN 입력, 구형 NPC 추정 제거,
란돌트 C 크기, 눈별 각도 회귀 및 범위 밖 입력 거부이다.
이 직접 검증은 Vitest 전체 테스트나 타입 검사·빌드·실기기 검증을 대체하지 않는다.
시선각도·절대 거리 정확도, 동공 윤곽 및 차폐 판독, 근접 촬영의 실제 지원 범위는 아직 확인되지 않았다.
